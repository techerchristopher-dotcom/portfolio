Projet

Un agent vocal qui travaille à votre place

AlloResa AI répond au téléphone dès la première sonnerie, 24h/7, sans jamais rater un appel. L'agent comprend la demande, vérifie les disponibilités en temps réel et confirme la réservation — le tout sans que le restaurateur n'ait à décrocher.

📞
Répond 24h/7
Ne manquez plus aucun appel. L'agent IA décroche instantanément, jour et nuit, même pendant le service ou en dehors des heures d'ouverture.
📅
Prend les réservations
L'IA vérifie les disponibilités en temps réel dans le système et réserve automatiquement — nom, date, heure, nombre de couverts, demandes spéciales.
🎯
Qualifie les demandes
L'agent collecte les informations clés, comprend les besoins (réservation, renseignements, annulation) et classe la demande automatiquement.
✉️
Envoie les confirmations
Email et SMS de confirmation envoyés automatiquement au client dès la réservation validée. Zéro suivi manuel pour l'équipe.

Automatisation

Pipeline MAKE — de l'appel à la réservation

14 nœuds MAKE orchestrent l'intégralité du flux : réception de l'appel vocal, transcription GPT, création client, vérification des disponibilités, réservation dans Airtable et Bubble, confirmation Google Calendar et SMS.

⚡ Webhooks→ 🌐 HTTP request→ 🧠 GPT transcript→ 👤 Création client→ ✏️ Update ID text→ 🧰 Tools→ 📅 Google Calendar→ 🌐 HTTP (SMS)→ 📊 Airtable update→ 🔍 Search ID resa→ 🪑 Search dispo/couverts→ 📱 Bubble create→ 📱 Bubble update→ 📊 Airtable update
01
Déclencheur appel
Un webhook reçoit l'appel entrant depuis l'API vocale. Déclenchement immédiat du pipeline à chaque appel.
Webhooks
02
Requête API vocale
Connexion à l'API de téléphonie IA pour récupérer l'audio de l'appel et initier la session de conversation.
HTTP (legacy)
03
Transcription & analyse GPT
GPT transcrit la conversation, identifie l'intention (réservation / renseignements / annulation), extrait nom, date, heure, couverts.
GPT transcript
04
Création client dans Airtable
Si le client n'existe pas, une fiche est créée automatiquement dans la base Airtable avec nom, téléphone et historique des visites.
Airtable · Create
05
Mise à jour ID → texte
L'ID Airtable du client est converti en texte pour être utilisé dans les étapes suivantes du pipeline.
Update ID en text
06
Set variable — contexte réservation
Les variables de la réservation (date, heure, couverts, demandes spéciales) sont stockées pour les étapes suivantes.
Tools · Set variable
07
Création événement Google Calendar
L'événement de réservation est créé dans l'agenda du restaurant — visible par toute l'équipe en temps réel.
Google Calendar
08
Envoi confirmation SMS/email
Requête HTTP vers l'API de notification — SMS de confirmation envoyé au client avec date, heure, nom du restaurant.
HTTP · SMS API
09
Mise à jour Airtable — statut
La fiche réservation dans Airtable est mise à jour avec le statut "confirmé" et le lien vers l'événement Calendar.
Airtable · Update
10
Recherche ID réservation
Recherche dans Airtable pour récupérer l'ID de la réservation fraîchement créée — nécessaire pour les étapes Bubble.
Search ID reservation
11
Vérification dispo & couverts
Recherche dans la table des disponibilités et des couverts pour valider que le créneau est bien libre avant confirmation finale.
Search table dispo/couvert
12
Création dans Bubble (app mobile)
La réservation est créée dans la base de données Bubble — elle apparaît immédiatement dans l'application mobile du restaurateur.
Bubble · Create
13
Mise à jour Bubble
Les détails supplémentaires (statut, lien Calendar, ID client Airtable) sont ajoutés à la fiche Bubble.
Bubble · Update
14
Synchronisation finale Airtable
Dernière mise à jour Airtable pour synchroniser l'ID Bubble — les deux bases restent cohérentes en permanence.
Airtable · Final sync

Interface

Dashboard web + application mobile restaurateur

Le restaurateur suit ses appels et réservations en temps réel sur le dashboard web. L'app mobile Bubble lui donne une vue complète de son carnet directement sur son téléphone.
